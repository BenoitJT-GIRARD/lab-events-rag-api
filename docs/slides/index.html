Base Vectorielle FAISS — Stratégies d'Indexation

Choix retenu : Flat Index (IndexFlatL2) — adapté à un POC < 5 000 vecteurs

Stratégie Principe Cas d'usage
Flat Index CHOIX Recherche exhaustive — compare la requête à TOUS les vecteurs < 5K vecteurs, POC, précision maximale
IVF Partitionnement en clusters (Voronoï). Recherche dans k clusters proches 10K–10M vecteurs, bon compromis vitesse/précision
HNSW Graphe navigable multi-niveaux. Traversée hiérarchique du graphe Haute performance en production, faible latence
PQ Compression des vecteurs — divise en sous-vecteurs quantifiés Millions de vecteurs, contraintes mémoire

Amélioration future : ajouter max_distance_threshold pour filtrer les documents trop éloignés sémantiquement

Évaluation RAGAS 0.4 — Métriques RAG Avancées

Métriques RAGAS

Métrique Score Interprétation
faithfulness 0.762 76% des réponses ancrées dans les docs — peu d'hallucinations
context_precision 0.575 57.5% des chunks récupérés sont utiles — bruit retrieval
context_recall 0.650 65% des infos nécessaires présentes — retrieval incomplet
answer_relevancy — Échecs API (rate limiting)
context_relevancy — Incompatible Mistral (métrique NVIDIA)

Interprétation

Le retrieval est le maillon faible

context_precision 0.575 → environ 4 chunks/10 inutiles

context_recall 0.650 → top_k=5 parfois insuffisant

faithfulness 0.762 → modèle globalement fidèle au contexte

Priorité : reranker + seuil distance FAISS

Limites & Pistes d'Amélioration

Limites actuelles

  • Corpus limité à Montpellier (configurable)
  • context_precision 0.575 → bruit retrieval
  • context_recall 0.650 → top_k fixe

  • Dépendance API Mistral
